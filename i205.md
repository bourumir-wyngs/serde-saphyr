# serde-saphyr issue #205: resolution review

- **Issue:** [Inconsistent alias errors and diagnostic output (#205)](https://github.com/bourumir-wyngs/serde-saphyr/issues/205)
- **Review date:** 2026-10-09
- **Baseline snapshot:** `master` at [`f1879ab7794b63d710e9dad78975d69c54825ca8`](https://github.com/bourumir-wyngs/serde-saphyr/commit/f1879ab7794b63d710e9dad78975d69c54825ca8). Items 1, 2, 3, 4, 5a, 5b, 5c, and 6a include subsequent local fixes; items 6b and 6c include subsequent local enhancements.
- **Method:** Static source and test inspection for the baseline; items 1, 2, 3, 4, 5a, 5b, 5c, and 6a additionally verified with regression tests that fail before their fixes and pass afterward. The new APIs in 6b and 6c are covered by unit, public-API integration, and documentation tests.

**Conclusion: all reviewed items are addressed locally.** The bug fixes are complete, and the enhancements in 6b and 6c now provide public path/location accessors, embedded-YAML line offsets, and a root source-name option. This document does not change the GitHub issue's state.

## Test caveats

- [Validation snippet tests](tests/garde/garde_validation_errors.rs) now expect the actual source name, replacing the old ` --> (defined):1:4` expectation that preserved the filename bug.
- [The alias source-chain test](tests/alias_error_issue_199.rs) now requires the immediate source to be the original typed error and rejects redundant intermediate wrappers. [Helper tests](src/de/tests.rs) also ensure distinct alias uses, including equal coordinates in different sources, retain their own wrappers.
- [PR #208's validation regression tests](https://github.com/bourumir-wyngs/serde-saphyr/blob/f1879ab7794b63d710e9dad78975d69c54825ca8/tests/garde/garde_validation_errors.rs#L374-L435) cover the resolved stray-include-note problem.

The baseline evidence remains tied to the pinned commit. The local fixes and enhancements described above supplement that review; they do not constitute a new audit of unrelated changes to `master`.
